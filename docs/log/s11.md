# S11 — Lessons + no-caption fallback UI

## Built

- `/lessons` (`src/app/lessons/`): GET-form filters (brand, `none` = portfolio-wide, kind,
  search) via `LessonFilters`, `LessonRow` list with delete, "Export Markdown" link.
- `/lessons/export` route: the same filter (`query.ts`) through `exportLessonsMarkdown` as a
  `.md` download, grouped by kind, video links at `&t=<sec>s`; 401 when signed out.
- `SaveLessonButton` `{ videoId, text?, timestampSec?, defaultBrandId? }`: inline form, text
  prefilled, kind + brand (brands fetched on first open via `lessonBrandOptionsAction`).
- `FallbackAnalyzeButton` `{ videoId, isOwner }`: null for employees; click → estimate,
  "Confirm · ~$x" → `analyzeWithoutCaptions`; refusal / cap text shown.
- `src/lib/lessons.actions.ts`: save, delete, brand options (any signed-in user); fallback
  estimate + run (`requireOwner`). All return `{ok}|{ok:false,error}`.
- `dict/lessons.ts` (36 keys, en + sv); `tests/integration/lessons-ui.test.ts` (6 tests).

## Decisions

- **Buttons exported only** — S9 mounts them in `src/app/youtube/video/**` (not S11's).
- **Actions return errors instead of throwing**, so the fallback's refusal text survives
  production's message stripping.
- **Lessons are open to any signed-in user** (save and delete): hand-written notes, no spend.
- **Export is a route, not an action**, so the link is a plain download of the current filter.

## Known issues

- `/lessons` uses the same `data-youtube-section` layout shell as `/inbox`; S5 removes that

- No nav link to `/lessons` yet — `Header.tsx` nav is S9's.
